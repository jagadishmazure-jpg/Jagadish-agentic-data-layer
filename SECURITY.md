# Security policy

This is a portfolio project. Nothing in it is deployed, and it holds no real customer data: every person, store and organisation is fictional and generated by code.

## Supported versions

Only the `main` branch is maintained.

## Report a vulnerability

Please report privately through GitHub: open the **Security** tab of this repository and choose **Report a vulnerability**. Private vulnerability reporting is switched on. Please do not open a public issue for a security problem.

Useful details:

- the file and line, or the command that shows the problem
- what an attacker could do with it
- a suggested fix, if you have one

You should get a first reply within a week.

## Security contact request

If private reporting does not work for you, open a public issue titled **Security contact request** with no details of the problem. A private channel will be arranged from there.

## What is in scope

- The data gateway (`src/adl/core/access.py`): any way for an agent identity to read a product, column or row it was not granted.
- The audit log (`src/adl/core/audit.py`): any undetected change to a record.
- The agent workflow (`src/adl/domains/retail/agents.py`): any way for retrieved text to cause an action, or for an approval to cover a changed action.
- The MCP and A2A interfaces (`src/adl/serve/`).
- The infrastructure code and workflows (`infra/`, `.github/`): over-broad permissions, public exposure, unpinned actions.

The threat model is in [docs/threat-model.md](docs/threat-model.md).

## Controls already in place

- Secret scanning with push protection, Dependabot alerts and security updates, CodeQL, gitleaks in CI.
- Every GitHub Action pinned to a commit SHA; workflows read-only by default; cloud access only through OIDC.
- checkov and tflint on every Terraform stack; skipped checks are listed with a reason in `.checkov.yaml`.
